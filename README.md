# AI Interview Coach

A real-time, voice-driven interview practice tool. Upload a job description PDF, get role-tailored questions, speak your answers, and receive instant AI-generated feedback plus a structured end-of-interview summary — all streamed over a single WebSocket.

## Highlights

- **JD-aware question generation.** Upload a PDF of the job description; five interview questions are generated by an LLM tailored to that role.
- **Voice-first loop.** Questions are synthesized to speech with `gTTS`; answers are recorded in the browser and evaluated from audio on the server.
- **Per-answer evaluation.** Every answer gets a structured critique (strengths, weaknesses, suggested improvements) streamed back immediately.
- **Final interview summary.** After the last question, a consolidated report grades the full session against the job description.
- **Single-connection protocol.** One WebSocket (`/ws/interview`) carries the JD upload, TTS question audio, user answer audio, evaluations, and the final summary.

## Architecture

```
Browser (index.html)
   │  PDF bytes
   ▼
FastAPI WebSocket  /ws/interview
   │
   ├── document_parser.parse_pdf_to_text   (pypdf)
   ├── question_generator.generate_questions_from_jd   (LLM via LangChain)
   │        → 5 questions
   ├── loop per question:
   │     ├── gTTS → base64 audio → client
   │     ├── client records answer → bytes → server
   │     └── answer_evaluator.evaluate_answer          (Whisper + LLM)
   └── summary_generator.generate_final_summary        (LLM)
```

Key modules:

- `app/main.py` — FastAPI app and WebSocket handler.
- `app/agents/question_generator.py` — JD → 5 tailored questions.
- `app/agents/answer_evaluator.py` — audio → transcript → structured critique.
- `app/agents/summary_generator.py` — full-interview report.
- `app/utils/document_parser.py` — PDF text extraction.
- `app/schemas.py` — Pydantic models for WebSocket messages and evaluations.
- `index.html` — minimal browser UI (upload JD, record answers, render feedback).

## Tech Stack

- **Backend:** FastAPI, Uvicorn, Pydantic
- **LLM orchestration:** LangChain
- **Speech-to-text:** `openai-whisper` (runs locally)
- **Text-to-speech:** `gTTS`
- **Document parsing:** `pypdf`
- **Frontend:** Single-page vanilla HTML/JS (`index.html`) using the Web Audio + MediaRecorder APIs

## Quick Start

```bash
# 1. Clone & enter
git clone https://github.com/sriv144/ai_interview_coach.git
cd ai_interview_coach

# 2. Create venv
python -m venv venv
# Windows
venv\Scripts\activate
# macOS / Linux
source venv/bin/activate

# 3. Install
pip install -r requirements.txt

# 4. Configure
cp .env.example .env
# edit .env and set your LLM API key

# 5. Run
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Then open `http://localhost:8000` in a modern browser, grant microphone permission, and upload a job-description PDF to start the interview.

## WebSocket Protocol

Connect to `ws://<host>/ws/interview`. The protocol is sequential:

1. Client sends the job-description PDF as **raw bytes**.
2. Server streams N messages of shape `{"type": "question", "data": {"text": "...", "audio": "<base64 mp3>"}}`.
3. For each question, client responds with the answer as **raw audio bytes** (webm/ogg/wav are all accepted; Whisper handles decoding).
4. Server replies with `{"type": "evaluation", "data": {...}}` for every answer.
5. After the last answer, server sends `{"type": "final_summary", "data": {...}}` and closes the socket.
6. Any error is emitted as `{"error": "<message>"}` before close.

Schemas are defined in `app/schemas.py`.

## Development Notes

- Whisper downloads model weights on first run; first launch is slower. Set `WHISPER_MODEL=base` (or `tiny`) in `.env` to trade accuracy for speed on laptops without a GPU.
- The WebSocket handler intentionally keeps all state in memory per connection; there is no persistence layer today.
- `gTTS` requires outbound HTTPS to Google. Offline use requires swapping in a local TTS (e.g. `pyttsx3`).
